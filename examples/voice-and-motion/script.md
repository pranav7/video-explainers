# Use order to skip work

For a curious adult. About half a minute. One continuous scene.

## Voice

Ellis. Normal speed. Read SQL as "sequel". Caption it as "SQL".

## Palette

| Concept | Colour |
| --- | --- |
| Remaining candidates | SKY |
| Current comparison | AMBER |
| Found value | MINT |
| Discarded candidates | FAINT |

## 1. SkipWork: Use order to skip work

- "Thirty-two sorted values. We want twenty-three. Do we have to check every value?"
  - Thirty-two upright marks form one ordered strip. Reveal the entire strip, then
    emphasize the target heading "FIND 23". Keep endpoint labels 1 and 32 readable. The target stays at
    the top of the composition.
- "Start in the middle. Sixteen is too low, so discard the entire lower half."
  - An amber cursor selects 16. The lower half drops and dims. A blue bracket
    contracts around the sixteen remaining marks. Record 16 in the comparison
    trail below the strip. Move the camera closer to the retained region.
- "Twenty-four is too high. Keep only the gap between them."
  - Move the same cursor to 24. The high values drop and dim. The bracket contracts
    to values 17 through 23. Add 24 to the trail. Replace "16 remain" with "7 remain".
- "Twenty is too low. Twenty-two is still too low. Try twenty-three. Found."
  - The cursor visits 20, then 22, then 23 on those spoken words. Each comparison
    contracts the same bracket. Append each value to the trail. The final mark and
    cursor turn mint on "Found".
- "Five comparisons. Binary search cuts the remaining range roughly in half. Ordered indexes in SQL also use order to skip work."
  - Return to the full composition. Keep all discarded marks as faint context.
    The completed trail reads 16 → 24 → 20 → 22 → 23. Replace the target heading
    with "5 comparisons" and add "Use order to skip work". End on the found value
    and its visible search path, then fade out.
